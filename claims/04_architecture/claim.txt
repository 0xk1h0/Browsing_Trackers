CLAIM 4 - How much an agent leaks is set by how the agent is built, not by
which model it runs.

Paper
    Abstract, Section 7.2, and Table 2.

Run
    bash claims/04_architecture/run.sh

    About 1 second. Recomputes the per-agent exposure summary over 1,286
    WebVoyager sessions per agent, 9,002 in total.

What you should see
    Means per session, sorted as Table 2 sorts them.

        agent          cross-site transitions   pseudonymous IDs
        OpenCUA-7B                       7.67              736.1
        Fara-7B                          5.89              447.0
        Browser-Use                      3.70              400.2
        SoM-GPT-5                        1.67              179.9
        UI-TARS                          0.77              123.7
        GUI-Owl-8B                       0.82              118.0
        SoM-GLM                          0.67              100.9

    UI-TARS and Fara-7B both run a Qwen2.5-VL-7B backbone, which the
    paper's Table 9 records, yet they differ by 7.6x in cross-site
    transitions and 3.6x in identifiers. That gap is the claim.

How this compares to the paper
    Five of the seven rows match Table 2 cell for cell on all eleven
    columns. Those are OpenCUA-7B, Fara-7B, Browser-Use, SoM-GPT-5, and
    GUI-Owl-8B.

    Two rows do not match, and they differ on most columns, not only the
    two shown above. SoM-GLM differs on ten of eleven columns, printing 1.9
    cross-site transitions and 211.2 identifiers where the data gives 0.67
    and 100.9. UI-TARS differs on nine of eleven, printing 1.3 and 150.8
    where the data gives 0.77 and 123.7. The paper's own Table 7 already
    prints 0.7 for SoM-GLM, which is the value the data supports. See
    artifact/CLAIMS.md, corrections C1 and C2.

    This run does not produce Table 3's action-space affordance columns.
    artifact/CLAIMS.md marks them as not reproducible from shipped data.
    Note also that OpenCUA-7B leads the cross-site column while exposing no
    named navigation primitive. Section 7.2 says the same, under "Primitive
    presence is sufficient, not necessary".

Checking it yourself
    Recompute both means straight from the per-session records, or run
    python3 artifact/verify.py rq2.

        python3 claims/04_architecture/expected/recompute_table2.py
