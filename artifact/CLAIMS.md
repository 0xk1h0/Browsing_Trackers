# Claim-to-artifact mapping

Every table, figure, and headline quantitative claim in the paper, the script
that produces it, the file that holds the result, and whether the artifact
reproduces the printed value.

Every value in the "Reproduced" column was read from a file regenerated by a
clean run, not transcribed from the paper. Reproduce them with:

```bash
bash install.sh
bash artifact/REPRODUCE.sh               # everything, about 4 seconds
bash claims/01_matched_exposure/run.sh   # or one claim at a time
```

Paths below are relative to `artifact/` unless they start with `claims/`.

Status vocabulary:

- **matches** — the artifact produces the printed value, to the precision printed.
- **differs** — the artifact produces a different value from the shipped data.
  Every case is itemized in [Corrections applied in the camera-ready](#corrections-applied-in-the-camera-ready).
- **not reproducible from shipped data** — with the reason given inline.

Two notes on how Table 2's columns are defined, so a reviewer can check the
definitions rather than infer them.

- **Tracking hosts** is `unique_tracker_domains`, the count of distinct tracker
  hosts across all requests in the session. The records also carry
  `nav_tracker_host_count`, which counts tracker hosts on the navigation chain
  only and is a different, smaller quantity. The paper's column is the former.
- **Operational success** is the per-session boolean `operational_success`
  recorded at collection time, not a quantity this artifact re-derives.
  Re-deriving it from its stated parts, at least three navigation requests with
  no crash and no timeout, agrees with the stored flag on 91 to 100% of sessions
  per agent but does not reproduce the paper's column for any agent, whereas the
  stored flag reproduces it exactly for five of the seven. The stored flag is
  therefore the one the paper used. It is not answer accuracy; `task_success` is
  null on every record.

## Corrections applied in the camera-ready

The accepted PDF is the version the program committee reviewed, and it is
textually identical to the submitted version. It therefore still carries the
values the authors committed to correcting in the author response, plus three
row-level discrepancies found while preparing this artifact. The artifact
reflects the corrected value in every case.

**C1 — Table 2 and Table 7, SoM-GLM.** The whole row is affected, not two
cells: ten of its eleven Table 2 columns differ, and only the cross-site median
of 1.0 matches. The headline values are cross-site mean 1.9 printed against 0.7
reproduced, pseudonymous-identifier mean 211.2 against 100.9, and Mind2Web
shift +283% against +301.5%. The Table 7 shift is not a separate error. Taking
the paper's own printed WebVoyager value of 0.7 against the same Mind2Web mean
of 2.68 gives +283.1%, so Table 7's SoM-GLM row is internally consistent and
only Table 2's 1.9 has to change. The printed pair is not derivable from any collection run of
this agent; both runs give approximately 0.67 and 100.9. The paper's own
Table 7 already prints 0.7 for this agent, so adopting the reproduced value
makes Tables 2 and 7 agree.

**C2 — Table 2 and Table 7, UI-TARS.** Nine of its eleven Table 2 columns
differ; the cross-site median and the tracker-host median match. The headline
values are cross-site mean 1.3 printed against 0.8 reproduced,
pseudonymous-identifier mean 150.8 against 123.7, and Mind2Web shift -28%
against +21.5%. Two Table 1 cells follow from the same run choice. The printed pseudonymous mean matches a second, longer
collection run of 2,944 sessions, while the caption's stated pool and this
artifact use the 1,286-session run. The camera-ready reports one run
consistently and states its n. Because the printed value makes UI-TARS the
second exception, Section 8's "5 of 7 agents traverse more on Mind2Web"
becomes 6 of 7 once the row comes from a single run.

**C3 — Table 6, two Browser-Use pseudonymous medians.** Printed C0 is 227 where
the shipped data gives 346, and printed C5 is 185 where the data gives 285. The
C2, C7 and C8 cells reproduce exactly, as do all five Fara-7B cells. Because C7
reproduces at 54, the reduction for Browser-Use becomes 84.4% against the
corrected baseline rather than 76%, and the abstract's range becomes 69 to 84%.
The correction makes the reported mitigation stronger, not weaker. The C5
negative control still behaves as the paper describes, moving 346 to 285.

**C4 — Table 6, operational success, and its conflict with Table 2.** The
printed C0 rates of 89.5% and 36.8% are not derivable from any shipped file.
Two different reproducible rates exist for the same agents in the same default
condition, and a single reproduction run prints both: Table 2 reports 92.5% for
Fara-7B and 37.2% for Browser-Use from the 1,286-session benchmark pool, while
Table 6's C0 cell reports 54.6% and 99.5% from the separately collected
643-session ablation batch. The two come from different collections and, for
Browser-Use, differ by 62 pp, so they must not be read as the same quantity. As committed in the author response, the camera-ready replaces
operational success with graded WebVoyager task success throughout, which
removes this column rather than restating it.

**C5 — Utility cost.** Printed: 4 pp on Browser-Use and 11.5 pp on Fara-7B.
Corrected: graded WebVoyager task success for C0, C2, and C7 gives 65.6 / 45.4
/ 49.6% for Fara-7B and 49.6 / 40.0 / 42.0% for Browser-Use, so the C7 cost is
16.0 pp and 7.6 pp, both significant under exact McNemar tests over the 643
paired tasks. This grading was produced after acceptance, in response to the
review, by re-scoring the stored agent answers per ablation condition with the
paper's GPT-4o judge. The per-condition verdicts are not part of this release:
`rq3_ablation/data/rq3_643/task_accuracy_eval.json` carries per-agent totals
for the default condition only and cannot yield these numbers. Treat C5 as a
camera-ready correction supported by the collection tree, not as a claim this
artifact reproduces. The ablation-condition success rates this artifact does
produce are the operational-success rates in
`data/rq3_643/full_metrics_per_cell.csv`, which are a different metric.

**C6 — Table 8.** The sampling unit is the telemetry field that triggers
classification, not the request: 60 fields per predicted class across six
classes, 360 in all, drawn from 295 requests. One of the six class rows was
omitted in print and is restored. Because sampling is stratified by predicted
class, the raw recall of 0.71 is not a population estimate; weighting each
stratum by its population prevalence gives 0.992 at precision 1.00, and all 24
false negatives fall into another leakage class rather than being missed.

**C7 — Table 1 granularity.** Unchanged, but clarified: Table 1 counts hosts
rather than eTLD+1, because distinct endpoints are separately blockable.
Re-aggregating the same traces at eTLD+1 preserves the gap, with a human median
of 2 against 3 to 6 across agents.

## Appendix A component names

The paper's Appendix A lists what the authors release and names three analysis
scripts by their development filenames. Those names were reorganized by
research question before release. The functionality is present under the names
below; the camera-ready uses the released names.

| Appendix A name | What it does | Released as |
|---|---|---|
| `analyze_e1_multiagent.py` | Hodges-Lehmann shift, Wilcoxon, bootstrap CIs on the matched pool | `rq1_human_vs_agent/analyze_rq1.py` |
| `run_e5_navigation_intervention.py` | post-hoc dose-response over cross-site transition bins | `rq2_dose_response/analyze_table3.py` and `plot_dose_response.py` |
| `run_e6plus_validation.py` | runtime enforcement of the proxy-layer restrictions | `rq3_ablation/interventions/proxy_filters/rq3_enforcement.py`, exercised by `rq3_ablation/scripts/run_fara_ablation.py` and `run_bu_ablation.py` |

The other four items Appendix A promises are present as named: the measurement
pipeline under `pipeline/`, the seven agent runner wrappers and their registry
under `agents/`, the seven filter-list snapshots under
`pipeline/classifier/tracker_lists/` (537,607 rules, verifiable with
`cat pipeline/classifier/tracker_lists/*.txt | wc -l`), and the per-session
anonymized records under `rq2_dose_response/data/paired_sessions/` and
`cross_benchmark/data/paired_sessions/`.

**C8 — Section 6.2, the two CMP denominators.** The paper reports two
statistics on two different populations and says so: Accept in 78.3% of 1,517
CMP-CDN encounters, and reject in 6 of 361 log-decided interactions, where the
361 subset is restricted to sessions with a deterministically parsed IAB TCF v2
consent string and an attributable click target. The artifact reproduces the
361-subset statistic exactly, 355 accepts and 6 rejects, which is the paper's
1.7% reject rate. It does not reproduce the 78.3% figure, because the
classification of the undecided remainder of the 1,517 is not part of this
release, and it does not contain the sham-split control sessions at all. Those
two results should be read as supported by the collection tree rather than by
this artifact, and the camera-ready states the two denominators side by side so
the 98.3% and the 78.3% are not mistaken for the same quantity.

**C9 — Ablation session count.** The paper describes the RQ3 ablation as 5,787
sessions, which is nine conditions at 643 tasks. The release ships ten
agent-condition cells at 643 sessions each, so 6,430, covering conditions C0,
C2, C5, C7 and C8 on two agents. The 5,787 figure is not derivable from the
shipped data, and four of the nine conditions in Table 5 have no 643-scale data
in this release. The camera-ready states the shipped design.

## Agent step budgets

`agents/registry.json` records the budget actually used for each agent:
Fara-7B at 30 rounds and the other six at 100 steps, with session timeouts of
300 s for Fara-7B, 500 s for Browser-Use, and 600 s for the rest. The paper's
Table 9 prints 100 steps for all seven and the timeouts as recorded. The
Fara-7B steps cell is corrected in the camera-ready to 30; the six other rows
and all seven timeouts match the registry.

## What this release deliberately does not contain

- **Raw HTTP flow bodies and raw cookie values.** Withheld under the human
  study's IRB protocol. Cookie values appear only as per-campaign salted
  hashes, and the salt is not released. Every claim above is derivable from
  what is released.
- **The Table 8 labeling sample and its scoring script.** Part of the
  collection tree rather than this release, which is why that row is marked
  not reproducible here.
- **The original collection itself.** It ran against the live web between
  March 22 and April 13, 2026 and consumed roughly 500 GPU-hours plus paid API
  usage. The pipeline is released for inspection and single-session
  demonstration under `pipeline/`, but re-running it cannot reproduce the
  paper's numbers and is not proposed for evaluation.
